# Maintain the tooling

## When to use

- Upgrading packages or the toolkit itself.
- Installing or removing Git hooks.
- Running a Fallout target that has no make target.
- Adding make targets, or keeping the agent skills in step with them.

## Workflows

**Upgrade dependencies**: `make upgrade_dependencies INSTALL_TOOL=true` lists outdated packages; with the user's
agreement, add `UPGRADE=true`. Respect the compatibility notes in `Directory.Packages.props`, read the release notes of
upgraded `Anarchy.Toolkit.*` packages for breaking changes, then run `make compile test_unit`. Without the flags it
prompts, which fails in non-interactive shells.

**Git hooks**: `make git_hooks_enable OPTIONS="--dry-run"` previews the pre-commit hook (lint fix and tests); run it
without `--dry-run` once the user agrees. `--force` replaces an existing hook: ask first.

**Build targets**: every operation has a make target; for anything else, `make fallout_help` lists the Fallout targets
and parameters, and `make fallout TARGET="<Target> --<Parameter> <value>"` runs one.

**Boilerplate**: `make boilerplate ITEMS=Makefile,scripts APPEND=true` installs packaged files into the solution. It
never overwrites: on a conflict it writes nothing and lists the files. To pick up a newer Makefile or scripts, compare
with the packaged ones and propose the changes to the user.

**Agent skills**: skills live in `.agents/skills/<name>/SKILL.md`. A `#@ <skill>` comment ties make targets to a skill:
at the top of a `.mk` file for all its documented (`#?`) targets, or right below one target for just that one (`#@ -`
exempts it; a bare `#@` means `<solution-prefix>-<file>`).
1. When adding a make target, document it with `#?` (and `#+ VAR|type|description` for its variables) and mark it.
2. `make skills_sync` creates missing skills from a template and rewrites only the block between the
   `anarchy:commands` markers. Everything else in a skill is free text: replace the template's TODOs with when to use
   the commands and how to combine them, as this skill does.
3. `make skills_validate` (run in CI) fails on missing skills, placeholder descriptions, missing `## When to use` or
   `## Commands` sections, or outdated commands.

`make install_skills` (or `anarchy-toolkit skills install`) installs the toolkit's skills; existing files are kept.

| `make fallout` or `make nuke` | Runs any target via the build project (nuke is a compatibility alias) | `TARGET` (str): Name of the target defined in the build project<br>`ENV` (str): Set to "ci" to run it as a CI build (--IsCiBuild true) |
| `make fallout_help` or `make nuke_help` | Prints the build project's help information |  |
| `make upgrade_dependencies` | Allows for upgrading all solution dependencies at once | `LOCK` (str): Specifies whether package versions should be partially locked. Possible values: "Major" (default), "Minor" or "None".<br>`INSTALL_TOOL` (bool): Allow installing or reinstalling dotnet-outdated without prompting (DEFAULT=false)<br>`UPGRADE` (bool): Allow upgrading without prompting (DEFAULT=false) |
| `make git_get_head_sha` | Gets the current HEAD SHA of the Git repository |  |
| `make git_hooks_enable` | Sets up a GIT hook | `OPTIONS` (str): Set to "--help" to display more options |
| `make git_hooks_disable` | Removes a configured Git Hook | `HOOK_TYPE` (str): Name of the hook (default: pre-commit) |
