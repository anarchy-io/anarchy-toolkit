# Package Catalog

The packages are the **Infrastructure** and **Build Ecosystem** pillars of the [Anarchy I/O Toolkit platform](../README.md#the-three-pillars), each adoptable on its own. Every project under `src/` is one package. Its package ID, assembly name and root namespace are all `Anarchy.Toolkit.<project name>` (`src/Core.Events/` → `Anarchy.Toolkit.Core.Events`). Each package's README, linked below, is also displayed on NuGet.org.

![Stacked modular blocks forming layers, flat outline illustration, dark background with red-orange accent, wide banner](../assets/images/headers/packages.png)

> **New here?** The [`anarchy-toolkit` CLI tool](Automation.Build.Cli/README.md) and the [`Automation.Build`](Automation.Build/README.md) build components are the quickest way in; see [Getting Started](../getting-started/README.md).
{: .notice--primary}

Packages are grouped by [layer](../guides/architecture.md): a package may depend only on its own layer or the layers below it, and, in this repository, within a layer mostly on its name ancestors (`Runtime.Web.MockServer.Ui` on `Runtime.Web.MockServer`), with a few listed exceptions checked by `make check_package_hierarchy`. The [dependency map](../guides/architecture.md#dependency-map) draws these references.

Every package is published to NuGet.org under the [`anarchy-io` profile](https://www.nuget.org/profiles/anarchy-io); the 📦 next to each name opens its NuGet.org page.

**Legend:** **[Abs]** abstractions only · **[Impl]** concrete implementation. *Depends on* lists sibling toolkit packages only (framework and NuGet dependencies are omitted; see [Third-party dependencies](third-party-dependencies.md) for the libraries a package brings that its name does not announce).

## Which package do I need?

Packages that share a family name are split by role. The parent holds what every provider shares; the suffix or sibling adds one concern. Pick by what your project does.

| If you need... | Install | Notes |
|---|---|---|
| The build and command-line operations as a library: scaffolding, layering checks, release versioning and notes, Git hooks, boilerplate | [`Automation`](Automation/README.md) | Referenced by the two packages below; reference it directly only to write your own tooling on top. |
| Build targets for a solution (compile, lint, test, layering, pack, release, Docker) | [`Automation.Build`](Automation.Build/README.md) | Referenced from `build/_build.csproj`; brings `Automation`. |
| The `anarchy-toolkit` command (`bootstrap`, `scaffold`, `config`, `skills install`) | [`Automation.Build.Cli`](Automation.Build.Cli/README.md) | A .NET global tool, not a project reference; it uses `Automation` and `Automation.Build`. Preferences are optional. |
| Relational persistence for an application: unit of work, repository bases, policies, health reports | [`Infrastructure.Persistence.Db.Postgres`](Infrastructure.Persistence.Db.Postgres/README.md), [`.Oracle`](Infrastructure.Persistence.Db.Oracle/README.md) or [`.Mysql`](Infrastructure.Persistence.Db.Mysql/README.md) | One provider package per database; each brings `Infrastructure.Persistence.Db`. Reference `Infrastructure.Persistence.Db` itself only to write a new provider. |
| Integration tests against a real database | [`Testing.Db.Postgres`](Testing.Db.Postgres/README.md), [`.Oracle`](Testing.Db.Oracle/README.md) or [`.Mysql`](Testing.Db.Mysql/README.md) | Test projects only; one per provider, matching the persistence package. They bring `Testing.Db` (shared cleanup and mapping helpers). |
| Represent domain events as CloudEvents | [`Infrastructure.Messaging.CloudEvents`](Infrastructure.Messaging.CloudEvents/README.md) | Transport-independent mapping and structured JSON; delivery is a separate concern. |
| Store events and define a transactional outbox in a relational database | [`Infrastructure.Persistence.Db.Events`](Infrastructure.Persistence.Db.Events/README.md) | Add it next to a provider package; applications implement outbox repositories, and generic `Infrastructure.Persistence.Db` stays business-neutral. |
| Publish messages to Kafka | [`Infrastructure.Messaging.Kafka`](Infrastructure.Messaging.Kafka/README.md) | Kafka publisher and inbound mapping over the broker-neutral contracts; use [`Testing.Kafka`](Testing.Kafka/README.md) for fixtures and broker-backed consumers. |
| Logs and metrics through `AppTelemetry`, with whatever logging providers and OpenTelemetry exporters you register | [`Core.Telemetry`](Core.Telemetry/README.md) | Already brought by `Bootstrap`, `Runtime.Web` and `Runtime.Workers`. No Serilog or vendor dependency. |
| Serilog as your logging provider, console defaults for a tool, the correlation or structured-exception enrichers, log-based metrics | [`Infrastructure.Telemetry.Serilog`](Infrastructure.Telemetry.Serilog/README.md) | Optional, on top of `Core.Telemetry`. Skip it if you use the Microsoft providers or OpenTelemetry alone. |
| Run on AWS: KMS secrets, Secrets Manager, the Parameter Store, Lambda jobs or Lambda APIs | [`Bootstrap.Aws`](Bootstrap.Aws/README.md), [`Runtime.Aws`](Runtime.Aws/README.md), [`Runtime.Web.Aws`](Runtime.Web.Aws/README.md) | Opt-in: `Bootstrap`, `Runtime` and `Runtime.Web` reference no AWS SDK. Opt into KMS secrets with `ModuleLibConfiguration.WithSecretManagement(new ModuleAwsSecretManagement())`; test Lambda APIs with [`Testing.Runtime.Web.Aws`](Testing.Runtime.Web.Aws/README.md). |
| An OpenAPI document and Swagger UI for a REST API | [`Runtime.Web.Swagger`](Runtime.Web.Swagger/README.md) | Opt-in: `Runtime.Web` references neither Swashbuckle nor Microsoft.OpenApi. |
| Call an API protected by Microsoft Entra ID with certificate credentials | [`Infrastructure.Http.Msal`](Infrastructure.Http.Msal/README.md) | Opt-in: keeps MSAL out of `Infrastructure.Http`. |
| Send toolkit metrics to a DogStatsD-compatible receiver | [`Infrastructure.Telemetry.StatsD`](Infrastructure.Telemetry.StatsD/README.md) | Optional recorder; configure the endpoint and choose histograms or distributions. |

Each row's packages work without the others. See [Observability](../guides/observability.md) for how the telemetry packages fit together.
